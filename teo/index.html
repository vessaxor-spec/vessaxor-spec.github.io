TEO / CONTROL PLANE

v1.0.0 reference_operational

Who should do the work?

TEO resolves responsibility, effective risk, required capability, implementation eligibility, fallback, and verification before a result can become an evidence-bearing outcome.

01 / DEFINITION

Plain meaning first. Exact architecture second.

The public layer translates TEO without replacing its native terminology or authority model.

PLAIN LANGUAGE

TEO is a governed decision layer for AI work.

It decides which responsibility owns a task, what capability the work requires, which implementations are eligible, how fallback may occur, and when an independent verifier is mandatory.

EXACT SYSTEM CLAIM

Vendor-neutral orchestration specification and runnable reference control plane.

TEO separates what a task requires from which model implements it today. Provider access, credentials, subscriptions, and billing do not become routing authority.

02 / CONTROL PATH

Responsibility before implementation.

The current public control path resolves the task and its governing constraints before an implementation is selected.

TEO / CANONICAL FLOW
